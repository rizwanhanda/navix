1. Project Scope & Objectives
Infrastructure-Free Client-Side Positioning
  • Core Objective: Deliver accurate, turn-by-turn indoor wayfinding on standard consumer smartphones without venue partnerships.
  • Zero Hardware Requirement: Completely eliminates mandatory BLE beacon grids, Wi-Fi heatmaps, or pre-existing CAD floor plans.
  • Target Clients: Native mobile runtimes on Android (Kotlin) and iOS (Swift) for low-latency hardware sensor access.
2. Proposed Functions & Intended Users
Target Audience & System Capabilities
  • Target Demographics: University students, campus visitors, facility managers, and emergency response units.
  • Real-Time Navigation: 2D vector map guidance and 3D Augmented Reality camera ribbons.
  • Emergency Evacuation Mode: One-tap failsafe routing to the nearest verified emergency exit node during facility emergencies.
3. System Features & External Interfaces
Sensor Streams & Interface Boundaries
  • Motion Ingestion: 50Hz continuous IMU sampling, orientation-invariant magnetic field extraction, and barometric altimetry.
  • AR Visual Projection: Short-range 3D directional arrows placed 2.5m ahead on ARKit / ARCore Visual-Inertial Odometry coordinates.
  • Cloud Object Storage: Secure HTTPS S3 protocol pipeline for distributing floor graphs and versioned deliverables.
4. Motion Engine: Pedestrian Dead Reckoning
Step Impact & Stride Calculation Pipeline
  • Gait Impact Isolation: 1.0Hz to 3.0Hz digital bandpass filter extracts heel strikes from total acceleration magnitude invariant to phone tilt.
  • Adaptive Weinberg Stride Model: Dynamically calculates step length from vertical body bounce differences (a_max - a_min) instead of fixed distances.
  • Heading Stabilization: Fuses high-frequency gyroscope yaw rate with the 3-axis magnetometer to eliminate rotational drift.
5. State Space: Monte Carlo Particle Filter
Drift Elimination via Probability Clouds
  • Uncertainty Representation: Simulates 400 candidate position particles scattered across corridor layouts.
  • Hard Wall-Bounding: Binary corridor mask immediately prunes particles attempting to walk through solid architectural walls.
  • Multi-Factor Weights: Combines wall masks, ambient magnetic signatures, and weak GPS bounds into a single probability score.
6. Architecture: Client, Compute & Storage
Modular Tier Separation
  • Native Clients: Kotlin (Android) and Swift (iOS) sharing a standardized JSON parameter schema.
  • Backend Compute: Python FastAPI application orchestrating authentication, version control, and data pipeline tasks.
  • Storage & Hosting: GitHub Pages static frontend, self-managed compute backend, and S3-compatible Backblaze B2 cloud storage.
7. Performance Goals & Security Measures
Latency, Accuracy & Data Protection
  • Execution Latency: Sub-50ms particle filter calculation cycles ensuring smooth 60 FPS mobile UI rendering.
  • Spatial Accuracy: Mean localization accuracy within 1.8 meters inside structured corridor environments.
  • Anti-Corruption Filter: Velocity sanity checks (< 2.5 m/s) and DBSCAN K-consensus clustering (K ≥ 3) before promoting community map updates.
8. Reliability, Usability & Maintainability
Resilience & Cross-Platform Parity
  • 100% Offline Capability: Full local SQLite graph caching allows complete navigation without continuous cellular connectivity.
  • Adaptive View Switching: Tilt sensors toggle between AR camera view (upright) and 2D vector map (flat) to conserve device battery.
  • Automated Parity Harness: Automated unit tests run identical sensor CSV datasets against both Swift and Kotlin engines to ensure algorithmic parity.
9. Technical Risks & Mitigation Strategies
Edge Cases & Fallbacks
  • Risk: Large Open Atriums: Lack of corridor walls causes particle spread. Mitigation: Magnetic anomaly gradient matching.
  • Risk: iOS Wi-Fi Throttling: iOS restricts background Wi-Fi scanning. Mitigation: 50Hz PDR, Magnetometer, and ARKit VIO odometry.
  • Risk: Barometer Drift: Air conditioning changes pressure. Mitigation: Relative pressure deltas paired with a manual floor rail selector.
