The Problem & Vision

The Problem

While GPS revolutionized outdoor navigation, it completely fails indoors due to satellite signal attenuation. Navigating large, complex indoor environments—such as university academic blocks, hospitals, expansive bazaars, and multi-story complexes—remains a frustrating experience. Furthermore, during high-stress situations like emergency evacuations, the lack of clear, localized routing can lead to chaos.

Intended Users

Students, faculty, hospital visitors, shoppers, and emergency responders who need accurate, infrastructure-free offline routing without relying on static physical maps or costly Wi-Fi/BLE beacon installations.

Reason for Selection

We selected this problem because it presents a rigorous Computer Science challenge—combining real-time IMU sensor fusion, Monte Carlo probabilistic localization, and 3D multi-floor graph theory—while directly solving a high-impact real-world problem.

Our Solution & User Journey

Proposed Solution: IndoorPulse

IndoorPulse is an offline-first, infrastructure-free Indoor Positioning System (IPS) for Android paired with a cloud-backed Web Map Console. The Android client uses Pedestrian Dead Reckoning (PDR) driven by hardware IMU sensors and stabilized by a 400-particle Monte Carlo filter, while the web interface enables portable JSON map inspection, cloud archiving, and browser-based 3D A* route simulation.

The Main User Journey

  • Surveyor Mode & JSON Packaging: An administrator maps the physical building by placing typed nodes (Building Entry, Waypoint, Stairs, Room Door) across floors and exporting a versioned JSON map package with automatic UUID translation.
  • Calibration & Multi-Floor A* Routing: A user selects a building or imports a JSON map, picks a destination (or triggers Emergency SOS), and the 3D Euclidean A* engine computes the optimal multi-floor route without floor-bleed.
  • Real-Time Navigation & Transit State UX: As the user walks, the app tracks steps and gyro heading via a live navigation chevron, automatically pausing PDR integration when entering stairwell vertical portals.

Live Demonstration Plan

Scenario: End-to-end multi-floor mapping, JSON export to the web console, and live PDR + A* navigation.

  • Step 1: Launch IndoorPulse on Android and load a multi-floor building topology from local Room persistence or exported JSON.
  • Step 2: Request a cross-floor route (or trigger SOS Emergency Exit) and observe 3D Euclidean A* calculate the optimal path across floor portals.
  • Step 3: Walk physically with the Android device—the Schmitt Trigger step detector and 400-particle filter advance the gyro-locked navigation chevron along the corridor while ignoring hand jitter.
  • Step 4: Import the same exported `.json` map package into the Web Map Console above to verify cross-floor topology and simulate the A* route directly in the browser.

System Integration & Architecture

Algorithmic Backend (PDR, Particle Filter & 3D A*)

  • Hardware Interface: Android SensorManager polls TYPE_LINEAR_ACCELERATION and TYPE_ROTATION_VECTOR at high frequency.
  • KinematicPDR.kt: Processes raw IMU streams via a Dual-Threshold Schmitt Trigger and Fused Biomechanical stride model, with automatic stairwell Transit State pausing.
  • ParticleFilter.kt: 400-particle Monte Carlo localization engine translating World Space headings into Map Space coordinates with wall/corridor constraints.
  • 3D A* Routing Engine: Multi-floor A* pathfinder with 3D Euclidean heuristics and vertical portal edge weights, plus strict Emergency SOS exit targeting.

UI Layer, JSON Engine & Cloud Persistence

  • Android UI Layer: Jetpack Compose (MapCanvas.kt, MainScreen.kt) with interactive multi-floor zooming, touch hit-detection snapping, and undo/redo Surveyor controls.
  • Portable JSON Map Engine: Full export/import pipeline with UUID translation, geofence radius metadata, and Room SQLite persistence.
  • 3-Tier Web & Cloud Stack: GitHub Pages static web console + AWS EC2 Flask API (`indoorpulse.duckdns.org`) + Backblaze B2 S3-compatible object storage.

Project Status

Completed & Deployed Modules

  • IMU PDR & 400-Particle Filter: Zero stationary drift with fused biomechanical stride estimation and chirality translation.
  • Multi-Floor 3D A* Routing & SOS Mode: Upgraded from Dijkstra to 3D Euclidean A* across vertical portals, with proximity-based stairwell Transit State UX and 1-tap SOS exit routing.
  • Surveyor Mode & JSON Export/Import Engine: Undo/redo graph editing, snapping hit-detection, sanitized versioned filenames, and UUID translation.
  • Web Map Console & Cloud Gateway: Interactive HTML5 Canvas multi-floor map explorer + AWS EC2 & Backblaze B2 artifact storage.

Future Scope & Research Extensions

  • Barometric Auto-Floor Detection: Fusing smartphone pressure sensor deltas to auto-confirm stairwell floor completion without manual confirmation.
  • Opportunistic Wi-Fi/BLE Drift Clamping: Optional passive RSSI landmarks where building beacons happen to exist.
  • ARCore Visual Inertial Odometry (VIO): Camera feature-point anchoring for long, featureless atrium spaces.
