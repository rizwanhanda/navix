IndoorPulse: Offline-First Indoor Positioning

Client-side indoor navigation leveraging native smartphone sensor fusion (PDR, Particle Filtering) with short-range AR wayfinding overlays.

The Problem & Vision

The Problem

While GPS revolutionized outdoor navigation, it completely fails indoors due to satellite signal attenuation. Navigating large, complex indoor environments—such as university academic blocks, hospitals, expansive bazaars, and religious sites—remains a frustrating experience. Furthermore, during high-stress situations like emergency evacuations, the lack of clear, localized routing can lead to chaos.

Intended Users

Students, faculty, hospital patients, shoppers, and emergency responders who need accurate, offline routing without relying on static physical maps.

Reason for Selection

We selected this problem because it presents a rigorous Computer Science challenge—requiring real-time sensor fusion, probabilistic mathematics, and graph theory—while directly solving a localized issue with massive real-world scalability.

Our Solution & User Journey

Proposed Solution: IndoorPulse

IndoorPulse is an offline-first, peer-to-peer capable Indoor Positioning System (IPS) for Android. It uses Pedestrian Dead Reckoning (PDR) driven by the smartphone's IMU sensors, stabilized by a 2D Monte Carlo Particle Filter. Devices can map environments and share the graph data locally, requiring zero cloud infrastructure or expensive external hardware like BLE beacons.

The Main User Journey

  • Surveyor Mode: An admin walks the physical space, dropping nodes and connecting edges to build a topological map of the floor plan, saved to the local database.
  • Calibration: A standard user opens the app, stands at a known starting node, and aligns their physical heading.
  • Real-Time Navigation: The user walks naturally. The app tracks steps and orientation, rendering a live gyro-locked navigation chevron over a blue position puck, while Dijkstra's algorithm calculates the shortest path to their destination.

Live Demonstration Plan

Scenario: Navigating a mapped graph from a starting junction to a specific destination node.

  • Step 1: Launch IndoorPulse and observe the Room Database instantly fetch the stored topological graph.
  • Step 2: Request a route. Observe Dijkstra's algorithm successfully calculate and draw the shortest path across the nodes.
  • Step 3: Engage the PDR engine. The presenter will physically walk forward.
  • Step 4: Observe the Schmitt Trigger State Machine correctly identifying legitimate steps while ignoring hand-shake jitter.
  • Step 5: Observe the UI. The blue dot moves along the mapped trajectory, and the gyro-locked chevron instantly mirrors physical left/right turns.

System Integration & Architecture

Algorithmic Backend (PDR & SLAM)

  • Hardware Interface: Android SensorManager continuously polls TYPE_LINEAR_ACCELERATION and TYPE_ROTATION_VECTOR.
  • KinematicPDR.kt: Processes raw IMU data using a Dual-Threshold Schmitt Trigger and a Fused Biomechanical Model.
  • ParticleFilter.kt: A Monte Carlo localization engine translating physical World Space headings into Map Space coordinates.
  • Routing: Dijkstra's algorithm computes edge weights to find the shortest physical path.

UI Layer & Persistence Architecture

  • UI Layer: Jetpack Compose (MapCanvas.kt) reactively renders coordinates and dynamic rotation transforms.
  • Database: A localized Room Database (SQLite) storing NodeEntity and EdgeEntity topologies.
  • Cloud Integration: Decoupled architecture using GitHub Pages static frontend, AWS EC2 Flask compute server, and Backblaze B2 Object Storage.

Project Status

What is Complete (The Prototype)

  • Robust Pedestrian Dead Reckoning (PDR) immune to stationary desk-drifting.
  • Advanced Stride Estimation (Fused Bounce/Frequency model).
  • Particle Filter coordinate translation (World Space vs. Map Space chirality).
  • Shortest path routing using Dijkstra's algorithm.
  • Surveyor Mode with SQLite graph persistence.

What We Will Build Next

  • Multi-floor Navigation Logic: Implementing a manual floor-switch toggle for devices lacking barometric pressure sensors.
  • Advanced Routing: Upgrading pathfinding to the A* algorithm for optimized heuristic searching.
  • Enhanced Localization: Adding Wi-Fi fingerprinting anchors to auto-correct PDR drift.
  • Visual Inertial Odometry (VIO): Exploring Computer Vision integration for absolute positioning.
