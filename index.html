The Problem & Vision

The Problem

While GPS revolutionized outdoor navigation, satellite signals attenuate heavily inside multi-story concrete buildings. Navigating complex indoor spaces—such as university academic blocks, hospitals, underground transit hubs, and large commercial complexes—remains disorienting. Furthermore, most existing indoor positioning proposals require expensive Wi-Fi access point fingerprinting or Bluetooth Low Energy (BLE) beacon hardware, which fail during power outages and emergency evacuations.

Intended Users

Students, faculty, hospital visitors, campus newcomers, and emergency evacuees who need reliable, zero-infrastructure indoor wayfinding that operates 100% offline on standard Android smartphones.

Reason for Selection

We selected this problem because achieving sub-2-meter indoor localization without external RF beacons is a classic Computer Science & Systems challenge—requiring real-time inertial signal processing, 400-particle Monte Carlo probabilistic filtering, and multi-floor 3D graph algorithms.

Our Solution & User Journey

Proposed Solution: IndoorPulse

IndoorPulse is an infrastructure-free, offline-first Indoor Positioning System (IPS) built natively in Kotlin and Jetpack Compose, paired with a self-hosted AWS EC2 + Backblaze B2 Web Map Console. It requires zero Wi-Fi or Bluetooth beacons—relying purely on smartphone IMU sensors (Linear Accelerometer + Rotation Vector), a 400-particle Monte Carlo localization filter, ARCore Visual-Inertial Odometry (VIO) heading stabilization, and a 3D Euclidean A* multi-floor router.

The Main User Journey

  • 1. Outdoor-to-Indoor Geofence Handshake: The Outdoor Dashboard monitors live GPS proximity against mapped building geofences (`centerLat`, `centerLng`, `geofenceRadius`) and automatically prompts indoor handoff upon arrival (with manual indoor/outdoor override support).
  • 2. Surveyor Mode & Portable JSON Packaging: A mapper walks the building, dropping typed topological nodes (`Building Entry`, `Waypoint`, `Stairs`, `Room Door`) and linking corridors or cross-floor `vertical_portal` edges with full undo/redo history and dynamic touch-snapping, then exports a sanitized, versioned `.json` map package.
  • 3. Multi-Floor 3D A* & Emergency SOS Routing: A user selects any destination across floors—or taps the 1-click SOS Emergency Exit button—and the 3D Euclidean A* engine calculates the optimal cross-floor trajectory while preventing floor-bleed.
  • 4. Live IMU Navigation & Stairwell Transit State UX: As the user walks, the Dual-Threshold Schmitt Trigger and 400-particle filter advance the gyro-locked navigation chevron along corridors. Entering a stairwell proximity radius automatically triggers the modal Transit State overlay, pausing PDR step integration until the floor transition completes.

Live Demonstration Plan

Scenario: End-to-end multi-floor building survey, JSON map export, browser-based 3D A* verification, and live Android PDR navigation.

  • Step 1 (Surveyor & Persistence): Open IndoorPulse on Android, inspect the multi-floor building topology stored in Room SQLite, and export the versioned `.json` map package with UUID translation.
  • Step 2 (Cross-Floor 3D A* & SOS): Select an upper-floor room target (or trigger Emergency SOS) and observe the 3D Euclidean A* engine compute the path across `corridor` and `vertical_portal` stairwell edges.
  • Step 3 (Live IMU Walk & Schmitt Trigger): Walk physically with the smartphone—observe the Schmitt Trigger state machine reject hand-shake jitter while the 400-particle filter and gyro-locked chevron track movement and pause automatically inside the stairwell Transit State.
  • Step 4 (Web Map Console Parity): Load the exported `.json` map into the Web Map Console above (or pull it from Backblaze B2) to inspect floor blueprints and simulate the identical 3D A* route and Transit State in the browser.

System Integration & Architecture

On-Device Algorithmic Stack (Android Kotlin)

  • IMU Sensor Fusion (`KinematicPDR.kt`): Polls `TYPE_LINEAR_ACCELERATION` and `TYPE_ROTATION_VECTOR` via a Dual-Threshold Schmitt Trigger state machine and Fused Biomechanical stride estimator, eliminating stationary desk drift.
  • 400-Particle Monte Carlo Filter (`ParticleFilter.kt`): Probabilistic state estimation translating World Space headings into Map Space coordinates with corridor edge clamping and resampling.
  • ARCore VIO Stabilization: Integrates ARCore camera pose tracking to clamp gyro heading drift over long corridors without external beacons.
  • 3D Euclidean A* Router & Transit State: Replaces flat Dijkstra with multi-floor 3D A* heuristics (`dx, dy, dz`), strict Emergency SOS exit targeting, and proximity-based stairwell PDR pausing.

UI Layer, JSON Engine & 3-Tier Cloud Stack

  • Jetpack Compose UI (`MapCanvas.kt`, `MainScreen.kt`): Interactive multi-floor blueprint canvas with zoom-clamping, snapping hit-detection, responsive Building Manager dialogs, and outdoor geofence dashboard animations.
  • Room SQLite & JSON Map Engine: Relational `BuildingEntity`, `NodeEntity`, and `EdgeEntity` schemas paired with a custom JSON export/import engine supporting automatic UUID remapping upon import.
  • Self-Managed Cloud Deployment (No PaaS): Static Web Map Console on GitHub Pages communicating with a self-configured AWS EC2 Flask API (`indoorpulse.duckdns.org`) and Backblaze B2 S3-compatible object storage.

Project Status & Engineering Milestones

Completed & Deployed System Modules

  • Infrastructure-Free IMU PDR + 400-Particle Filter: Complete step detection, stride estimation, and World-to-Map chirality translation with zero Wi-Fi/BLE hardware dependency.
  • Multi-Floor 3D A* Routing & SOS Evacuation: Full cross-floor pathfinding across `vertical_portal` stairwells, proximity Transit State modal overlay, and 1-tap SOS routing to true building exits.
  • Surveyor Mode & Portable JSON Engine: Multi-floor node/edge placement, undo/redo stack, dynamic touch snapping, and versioned `.json` export/import with UUID translation.
  • Outdoor Geofence Handshake & ARCore Mode: Live GPS distance tracking with automatic indoor entry prompts, manual exit overrides, and ARCore camera stabilization.
  • Web Map Console & AWS EC2 / Backblaze B2 Gateway: Browser-based 3D A* blueprint simulator and password-protected cloud artifact/map storage.

Key Architectural Decisions & Future Scope

  • Why Zero Wi-Fi/BLE Fingerprinting: RF fingerprinting requires pre-installed beacons, breaks when routers change, and fails during power outages—IndoorPulse guarantees 100% self-contained offline operation.
  • Why 3D Euclidean A* Over Dijkstra: Standard Dijkstra caused cross-floor bleed; 3D A* with explicit `vertical_portal` penalty weights (`30m`) guarantees realistic stairwell routing.
  • Future Extension — Barometric Auto-Floor Confirmation: Using smartphone pressure sensor deltas (`TYPE_PRESSURE`) to auto-dismiss the stairwell Transit State modal upon reaching the target floor.
